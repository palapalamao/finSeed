# 派工、交接与汇报模板

每个任务保留一个主记录，已有信息用链接引用，不在每个聊天复制整份设计。

## 任务卡／开发交接

```text
任务 ID／链接：
目标：用户通过什么操作，得到什么可观察结果。
交付负责人／执行聊天：
状态／优先级：
允许修改的范围：
明确不做的内容：
已确认设计／业务规则：
依赖任务／共享文件负责人：
工作区／分支／基线提交或源码清单：
验收输入、操作和预期：
验证方式与所需环境：
候选交付位置／最后证据：
下一步／阻塞及解锁条件：
授权边界：以本次任务的用户指令为准；需要额外授权的操作单独列出。
```

拿到任务后先确认工作区、已有改动和成功标准，缺陷先复现。需求已确认就连续完成实现和相关验证，不重新设计或重复询问。仅在影响业务规则、范围、数据完整性或权限的重要歧义下提出必要问题。

## 开发交给测试

```text
任务 ID：
候选版本／包 SHA-256：
源码提交／清单与工作区：
本次行为变化：
复现步骤／固定输入／预期：
开发已执行的检查、结果和证据：
需要独立核对的业务值与边界：
中英文／手机／导出涉及范围：
测试实例／端口／数据归属：
未验证项及原因：
集成依赖和回滚方式：
```

候选冻结后，开发可做其他无冲突任务；不能在测试背后覆盖同一包、源码目录或运行实例。若修订候选，通知测试以新版本重新判断影响范围。

## 测试结果

```text
任务 ID／测试者：
验证对象：提交／源码清单、候选版本、包哈希。
环境：时区、项目、数据集与配置版本。
结果：通过／部分通过／不通过。
逐项验收：输入、预期、实际、证据路径或链接。
验证层级：离线／受控浏览器／隔离 FIN／目标现场 FIN。
失败项：影响、稳定复现和交回的任务负责人。
未覆盖内容：
建议下一步：可集成／修复后重验／待外部条件。
```

普通开发者可以自行验证普通任务；统计、历史、权限等高风险行为用独立期望或相应复核，不能把开发自己的断言当作独立证据。

## 发布交接

```text
版本／包含任务：
冻结源码提交或清单：
候选包路径／SHA-256／包内版本：
对应版本检查、构建、测试及运行验收证据：
目标环境／部署执行者／本次授权来源：
备份／回滚包与触发条件：
安装后版本、页面资源、关键查询和数据完整性结果：
结果：未部署／已部署待核验／核验通过／已回滚。
限制与下一步：
```

## 经理给用户的简报

```text
本期目标：
已验证交付：
正在执行：负责人 → 任务 → 下一步。
等待与阻塞：等待什么、由谁解除。
下一批任务：按优先顺序，不重复列已在开发的任务。
质量状态：通过哪些层级，哪些仍待验证。
需要你决定：只列会改变目标、范围、业务规则或授权的事项；没有则写无。
```

不要用“完成 90%”代替可验收结果。进度依据代码、候选和证据更新；聊天运行状态只用于判断是否有执行活动。
