# Frontend validation

`npm ci` installs the pinned toolchain. `npm run build` type-checks and builds the FIN-served assets. `npm test` checks relative date ranges, FIN response envelopes, immutable export snapshots and chart semantics. `npm run test:e2e` tests the production build in an isolated headless Edge browser (install Edge, or change the Playwright channel for CI).

The Playwright fixture intercepts only the authenticated FIN transport at `testproject`. It exists under `tests/e2e` and is never imported into the product. It does not contact FIN or mutate real points. These tests prove browser behavior and downloadable file structure against a controlled API contract; they are not FIN runtime acceptance evidence.

E2E coverage includes all statistical/analysis routes, raw trend, overview rotation/comparison, dynamic template periods and reset, configuration CRUD and meter-role changes, source-point bind/unbind, bulk reference inclusion/removal, group category alarms, tariff/calendar defaults, alarm acknowledgement, calculation/alarm tasks, all four actual download formats, read-only/403/401 states, missing project, missing source values, canvas content and mobile overflow. Failed runs retain screenshots/traces under the ignored `test-results` and `playwright-report` directories; download and visual evidence is attached to the corresponding successful test too.

The 1001-row export test tracks every rendered data row across bounded PDF viewports, checks that the last row is included in the workbook, and verifies that the explicitly scoped chart/summary PNG stays below the browser's tall-canvas limit. PDF expands the complete quality/source section before pagination.

For dashboard category rotation/hidden-category persistence, trend collapse and per-unit bounds, regression fit endpoints, utility percentages, reference aliases and daily peak/valley/flat bands, run `npm run test:e2e -- tests/e2e/dashboard-categories.spec.ts tests/e2e/visual-controls.spec.ts tests/e2e/daily-bands.spec.ts` after building. Final concentrated regression logs are saved under the ignored `validation-logs` directory.

`native-fin.spec.ts` is skipped by default. Only after the isolated registered FIN deployment and audited loopback bridge are ready, set `FINSEED_NATIVE=1` and run `npm run test:e2e -- tests/e2e/native-fin.spec.ts`. It forwards real business API calls through `127.0.0.1:4179/proxy` to `finseed-acceptance-local` or `finseed-acceptance-reader`, checks real 240 kWh/export evidence, creates and deletes only a uniquely named group, and checks actual reader permission rejection. The browser's local test-only attest value is not a FIN credential and does not verify native cookie login; native browser-session authentication is separate evidence. Credentials are never loaded or saved by these tests. Never retry a mutation whose outcome is unknown.
